skill 0.2.0 lets you say which kind of agent gets a skill, and adds `skill install`, which puts back everything a lockfile records. The global lockfile moves to `~/.config/skill/skills.lock`, so it can live with your dotfiles.

```sh
gem exec skill add anthropics/skills@pdf --agents coding
```

![skill installs pdf for the coding agents only and xlsx into a RubyLLM app's app/skills, then after the skills are deleted, skill install restores both from skills.lock](https://github.com/crmne/skill/raw/v0.2.0/docs/v0.2.0.gif)

## New

### Choose agents by group

```sh
skill add anthropics/skills@pdf --agents coding       # your coding agents, not your app
skill add anthropics/skills@pdf --agents ruby_llm     # your RubyLLM app's app/skills
skill add anthropics/skills@pdf --agents coding,ruby_llm
```

`--agent` is now `--agents`, and takes groups as well as names. `all`, the default, installs into every folder detected, RubyLLM's `app/skills` included in a RubyLLM project, as before. `coding` installs into every coding agent detected and never into `app/skills`, so a skill meant for the agent working on your code stays out of your app. Both fall back to `.agents/skills` when they detect nothing. `--agent` still works. By @crmne

### Install what a lockfile records

```sh
skill install           # the project's skills, after a fresh clone
skill install --global  # yours, on a new computer
```

Like `bundle install`, `skill install` installs each skill in `skills.lock` at its recorded commit into its recorded folders, creating any that are missing. Skills already in place are left alone, every download must match the recorded digest before anything is written, and copies you edited are replaced only with `--force`. It never moves a skill to a newer commit; that stays `skill update`'s job. With a source, `skill install owner/repo` still works like `skill add`. By @crmne

### The global lockfile lives in `~/.config/skill`

The global `skills.lock` records what you chose to install, like a Brewfile, so it now lives in `$XDG_CONFIG_HOME/skill` (`~/.config/skill`) instead of `~/.local/state/skill`. Keep it with your dotfiles, and `skill install --global` restores your skills anywhere. A lockfile in the old place moves the first time `skill` reads it, and `skill` says so. By @crmne

## Known limitations

* **GitHub and local folders only.** GitLab, other git hosts, and direct archive URLs are not supported yet.
* **Copies, not symlinks.** Each folder gets its own copy.
* **Windows is untested.**
